# 加简大白话 · Plainify 需求清单

更新时间：2026-09-04

## 记录规则

- 一个需求只解决一个问题。
- 新想法默认先进入需求清单，不直接进入开发。
- 开发前需要确定优先级、依赖关系和验收标准。
- 状态分为：待讨论、已确定、待设计、待开发、开发中。
- 已完成或决定不做的需求从清单删除，历史以 Git 记录为准。
- 优先级分为：P0 为阻塞当前版本发布的需求，P1 为发布前应完成的质量与反馈能力，P2 为后续迭代。

## 产品路线

### 第一阶段：本地单用户版

当前版本优先满足个人本地使用：用户可以从 GitHub 下载项目，在自己的电脑上运行网站、后端和浏览器扩展。

- 不要求注册或登录账号。
- 术语与复习数据保存在本机。
- DeepSeek、OpenAI、阿里云百炼、Moonshot AI 和智谱 AI 的 API Key 可以在前端设置页填写。
- 前端提交的 API Key 由本机后端写入受保护且不会提交到 Git 的配置文件。
- 浏览器扩展和网页通过本机后端调用当前选定的模型提供方。
- 网站设置页、网页悬停卡片、扩展生成提示和扩展实际请求使用后端当前生效的同一个模型提供方与具体模型；保存或切换模型后不得继续显示或调用旧提供方、旧模型。
- macOS 用户可以通过根目录 `install.command` 完成依赖安装、常驻服务安装和网站打开。
- Windows 10/11 用户可以从 GitHub README 复制一段 PowerShell 指令给能操作终端的 AI；`install-from-github.ps1` 将项目下载到 `%LOCALAPPDATA%\Plainify`，安装登录自启服务并打开网站。
- macOS 用户可以从 GitHub README 复制一段 Shell 指令给能操作终端的 AI；`install-from-github.sh` 将项目下载到 `~/Applications/Plainify`，安装登录自启服务并打开网站。
- 首次打开网站会按“连接模型、安装扩展、解释第一个词”显示可收起的上手进度；配置错误可以直接进入对应设置。
- 全量重新整理应用后，完成提示只报告分组结果和已删除的旧分组数量，不提示用户可以撤销。
- 通用设置将“浏览器扩展”“收录方式”和“网页悬停卡片”作为三个独立的同级卡片展示，并按该顺序排列；悬停内容使用单选列表，默认且首位展示“解释和类比”；扩展连接后自动同步，不提供手动同步按钮。
- 设置页不提供打开本机配置文件的入口；API Key 和自定义地址只通过模型配置表单读写。
- 网站顶栏展示“加简大白话 · Plainify｜用大白话，读懂复杂术语”，中英文产品名使用相同字体和字号；首页术语输入区不显示额外标题；桌面端设置使用留有页面背景的紧凑弹窗。

### 第二阶段：云账号版

产品成熟后增加账号体系和云端数据同步。

- 用户在不同电脑登录同一账号后看到同一份数据。
- 任意设备新增或修改数据后，其他设备自动获得更新。
- API Key 与账号绑定并安全保存在云端后端，不需要每台设备重复配置。
- 云端具体使用自建后端、Supabase，还是 iCloud/网盘方案，暂未确定。

## 文档验收记录

### 2026-09-04：Windows 和 macOS 统一复制命令安装

- 根 README 不再要求普通用户手动下载源码 ZIP、解压并双击安装文件；Windows 和 macOS 都提供可复制给 AI 或对应终端直接执行的安装命令。
- `install-from-github.ps1` 从官方仓库 `main` 分支下载最新源码到 `%LOCALAPPDATA%\Plainify`，复用完整的现有项目，不覆盖不完整的同名目录。
- Windows GitHub 引导脚本继续调用现有安装器，完成 Node.js 检查、锁定依赖安装、登录自启服务、健康检查和网页打开；缺少 Node.js 时安装后重新执行同一段命令即可。
- Windows CI 对 GitHub 引导脚本执行 PowerShell dry run；发布契约检查 README 命令、官方 API 地址、固定安装位置和无个人绝对路径约束。

### 2026-09-04：Windows 10/11 正式支持

- Windows 用户可以双击根目录 `install-windows.cmd`，自动检查 Node.js 20.19、安装锁定依赖、注册当前用户登录启动项、启动本机服务、完成健康检查并打开术语库网页，不要求管理员权限。
- Windows 后台守护脚本隐藏运行，将日志和进程状态写入项目 `.logs/`，服务异常退出后自动重启；重新安装时只终止可确认属于当前项目的旧服务进程。
- `npm run dev` 不再执行 Unix 专用的 `node_modules/.bin/vite`，Windows 与 macOS 使用同一个 Vite Node API；`npm run service:install` 和 `npm run service:status` 按当前系统分发。
- Windows 保存 `.env.local` 临时文件时先移除继承 ACL、只授予当前用户完全控制，再原子替换正式配置，不向命令输出 API Key。
- GitHub Actions 增加独立的 `windows-latest` 检查，执行依赖安装、lint、production build、核心测试、Windows 服务安装 dry run，以及前后端真实启动和健康检查。
- 根 README 和扩展 README 将 Windows 10/11 列为正式支持平台，说明复制命令安装、扩展加载、状态检查、日志与重新安装方式。
